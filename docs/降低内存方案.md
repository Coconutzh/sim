 # TapNow MVP 物理裁剪计划：Tools + Blocks + Tool Routes + Landing

  ## Summary

  - 目标：把当前 Sim 裁成内部 MVP，本地启动只保留画布、Agent、Copilot、文件、搜索、MCP、HTTP/API，以及演示必需的 slack、gmail、notion。
  - 范围：物理删除长尾第三方 tools、对应 blocks、/api/tools/** routes、landing integrations/gallery 展示数据，并重新生成 catalog。
  - 不碰：核心 workflow editor、realtime、auth/db/workspace 权限、workflow persistence、基础文件/知识库/日志/表格能力。
  - 预期收益：显著减少 Next route graph、工具/Block 编译面、catalog JSON 体积和 landing 静态数据加载面。

  ## Key Changes

  - 保留 Tool 能力
    - 保留 service：file、mcp、search、slack、gmail、notion。
    - 保留独立 tool id：http_request、search_tool、file_parser、file_parser_v2、file_parser_v3、file_append、file_write。
    - 删除其余 apps/sim/tools/{service}/**，并清理 apps/sim/tools/registry.ts、apps/sim/tools/loaders.generated.ts、apps/sim/tools/catalog.generated.json、apps/sim/tools/outputs.generated.json。
  - 保留 Block 能力
    - 保留 block type：agent、api、chat_trigger、condition、file、function、generic_webhook、loop、mcp、note、parallel、response、router、search、start_trigger、table、variables、webhook_request。
    - 删除其余长尾 service block：apps/sim/blocks/blocks/{service}.ts。
    - 同步清理 apps/sim/blocks/registry.ts，然后重新生成 apps/sim/blocks/catalog.generated.json 和 apps/sim/blocks/loaders.generated.ts。
    - 不保留 image_generator、video_generator 作为第一批核心块，避免连带保留多媒体 provider、视频/image API key UI 和重型展示链路。
  - 删除 Tool API Routes
    - 保留与上述 service/tool id 对应的 apps/sim/app/api/tools/** route。
    - 删除不再保留 service 的 apps/sim/app/api/tools/{service}/**。
    - 同步删除只服务于被删 tool route 的 contract、selector route、OAuth provider wiring、selector registry/type 项。
    - 删除后更新 scripts/check-api-validation-contracts.ts 的 route baseline，只记录真实 route 数变化，不放宽边界规则。
  - 删除 Landing / Marketing 集成展示
    - 删除公开 integration gallery 和详情页：apps/sim/app/(landing)/integrations/**。
    - 删除 integrations.json、icon-mapping.ts、popular-workflows.ts 等展示数据。
    - 从 landing navbar、structured data、footer、templates/features 中移除指向 /integrations 的入口。
    - 保留 landing 首页、pricing、terms/privacy、login/signup 所需页面；不删除 workspace settings 里的实际连接账户管理页。
    - /integrations 和 /integrations/[slug] 删除后返回 Next 404，不新增重定向。

  ## Implementation Steps

  - Batch 1：生成删除清单
    - 从当前 apps/sim/lib/product/tool-policy.ts 的 TapNow MVP 白名单生成保留 service/tool/block 清单。
    - 用脚本列出将删除的 tool services、tool routes、block files、OAuth/selector/contracts 引用。
    - 输出清单后再执行删除，避免误删保留项。
  - Batch 2：物理删除 tools/routes/blocks
    - 删除不在白名单内的 tools/{service}、app/api/tools/{service}、blocks/blocks/{service}.ts。
    - 清理 registry、OAuth、selector、contracts、icons 中只服务被删集成的引用。
    - 保留 note block 中对 YouTube/Spotify 等纯 embed 支持，除非它直接依赖已删除 tool/block。
  - Batch 3：删除 landing integrations
    - 删除 landing integration directory 和展示数据。
    - 清理 landing/nav/footer/SEO/structured-data 中的 integration 链接和 schema。
    - 如有测试引用 /integrations，改为验证该入口不再出现在 landing 导航中。
  - Batch 4：重新生成 catalog
    - 运行 bun run sim-tools:generate。
    - 运行 bun run sim-blocks:generate。
    - 检查 generated JSON 中不再包含已删 service/block。
    - 检查 apps/sim/tools/loaders.generated.ts 和 apps/sim/blocks/loaders.generated.ts 不再动态导入已删模块。

  ## Test Plan

  - bun run check:tool-registry-boundary
  - bun run check:api-validation
  - bun run check:realtime-prune
  - Set-Location apps\sim; bunx biome check 仅跑被改动文件
  - Set-Location apps\sim; bunx vitest run 跑与 registry、tool policy、landing SEO、workspace shell 相关测试
  - 本地 smoke：
    - bun run dev:full:local
    - 打开 /workspace
    - 新建 workflow
    - 添加并运行保留 block：Agent、API、File、Search、MCP、Slack/Gmail/Notion 中至少一个
    - 确认 /integrations 不再作为 landing 导航入口出现
    - 采样启动内存并与当前约 4.7GB–6.0GB WS 基线对比

  ## Assumptions

  - 第一批保留 slack、gmail、notion 作为演示集成；其余第三方 SaaS 默认删除。

  - 第一批不删除 realtime、workspace settings、auth、db、workflow execution、knowledge、files、logs、tables。

  - 第一批不保留 image/video generator，后续如演示需要再单独加回。

  - 删除是物理裁剪，不只是 env 白名单隐藏；因此必须同步生成 catalog 并修正 tests/baseline。

-  # 后续减内存路线图

    ## Summary

    - 先做一轮“高收益、低产品风险”的物理裁剪，再根据内存采样决定是否继续深裁。
    - 每一阶段都要记录：删除范围、route/tool/block/catalog 数量变化、启动内存峰值、验证命令。
    - 默认目标保持 TapNow MVP：内部画布产品优先，不维护完整 Sim 集成市场和公开营销目录。

    ## Phase 1：长尾 Tools 物理裁剪

    - 删除除 file、mcp、search、slack、gmail、notion 和 http_request 外的大部分 tool service。
    - 同步删除对应 apps/sim/app/api/tools/{service}/**、apps/sim/blocks/blocks/{service}.ts、registry、contract、selector、OAuth wiring。
    - 重新生成 tool/block catalog，并更新 API validation baseline。
    - 完成后采样 bun run dev:full:local 启动内存，作为第一轮收益基线。

    ## Phase 2：Landing / Marketing 精简

    - 删除 apps/sim/app/(landing)/integrations/** 和 integration gallery 数据。
    - 清理 navbar、footer、structured data、landing links 中的 /integrations 入口。
    - 保留首页、登录注册、pricing、terms/privacy；不再维护公开集成详情页。
    - 如 landing 仍较重，再考虑删除 blog/models/partners 等公开营销目录，但这作为第二决策点，不和 Phase 2 混做。

    ## Phase 3：依赖与锁文件瘦身

    - 根据被删 tool/service 反查 apps/sim/package.json 中只服务这些集成的 SDK。
    - 删除不再使用的重型依赖，例如云厂商 SDK、CRM/ATS/analytics SDK、浏览器自动化相关依赖。
    - 跑 bun install 更新 bun.lock。
    - 验证无残留 import、无 generated loader 指向已删模块。

    ## Phase 4：Workspace 首屏懒加载

    - 如果 Phase 1-3 后启动内存仍高，重点优化 /workspace 首屏编译链路。
    - 将非首屏内容延后：settings 深层页面、command palette/search data、block/tool picker 数据、preview/editor 重组件。
    - 保持 workspace shell 可用：sidebar、home gateway、基础权限和 canvas 跳转不能断。
    - 目标是让打开 /workspace 不立即编译完整 workflow editor、settings 全量面板和全部 catalog 使用场景。

    - 根据真实 MVP 演示路径，决定是否继续删：
      - 企业能力：SSO、audit logs、data retention、data drains、whitelabeling。
      - 公开站能力：blog、models directory、partners、demo request。
      - 高级文件预览：Monaco/PDF/Office/XLSX 只保留懒加载或移除。
    - 这一阶段风险高于前几阶段，必须一项一项删，不能大批量混删。

    ## Validation

    - 每阶段必跑：
      - bun run check:api-validation
      - bun run check:tool-registry-boundary
      - bun run check:realtime-prune
      - 针对改动文件的 bunx biome check
    - 每阶段 smoke：
      - bun run dev:full:local
      - 打开 /workspace
      - 创建 workflow
      - 添加并运行 Agent、API、File、Search、MCP
      - 如保留 Slack/Gmail/Notion，至少验证菜单和 credential UI 不报错
    - 每阶段记录指标：
      - API route 数
      - /api/tools/** route 数
      - tool service 数
      - tool/block catalog 文件大小
      - Next 启动后首次 /workspace 编译内存峰值

    ## Assumptions

    - Phase 1-2 可以直接执行，不需要再保留完整公开 integration marketplace。
    - 后续是否删除 blog/models/enterprise/billing，需要在 Phase 2 内存数据出来后再决定。
    - realtime、workflow editor、auth/db/workspace 权限不作为减内存删除目标，只做懒加载和边界保护。
